## v0.11.21

- **修复识别循环会静默停摆**（表现为「突然不买卡了」，且重新点开启也救不回来）：`tap()` 在手势被系统取消（`onCancelled`）、系统拒绝、抛异常三条路径上都没有释放 `ShopActionGate`，闸门 `inFlight` 永久占用；而 `scan()` 在 `delay()<0` 时是**直接 return 且不重排下一次**，于是从此再没有任何东西调 `scan()`。日志表现为 `phase=gesture` 卡住数分钟、只有 health 心跳、一条 `frame_ms` 都没有。
- 三处一起修：`ShopActionGate` 新增 `abort()` 无条件释放，`delay()` 加 3 秒超时自愈；`tap()` 三条异常路径补 `abort()` + `phase("idle")`；`scan()` 的 `delay()<0` 分支改为排一次 120ms 重试，不再单靠 `endGesture` 续跑。
- `phase("gesture")` 同样漏了复位，导致 heartbeat 一直显示 gesture，把真实原因盖住——这也是这次排查绕远路的原因。

## v0.11.20

- 修复投屏取帧**永远建立不起来**：`ProjectionService.start()` 曾经从授权 Intent 的 extra 里读 `resultCode`，但 resultCode 是 `onActivityResult` 的独立参数、不在 Intent 里，于是永远拿到 0，trace 报 `projection unavailable 投屏授权结果无效`。改为由调用方显式传入。
- 修复 K80 / HyperOS 的投屏授权弹窗**默认选「单个应用」**：那样只能录到本应用自己的界面、拍不到游戏，识别必然全黑。Android 14+ 改用 `createScreenCaptureIntent(MediaProjectionConfig.createConfigForDefaultDisplay())` 显式要求整个屏幕，弹窗不再提供单应用选项（已真机确认选项消失）。
- 投屏取帧未授权时的重试间隔从 150ms 放宽到 2000ms：这是稳定状态，按取帧节奏空转只会白刷日志。

## v0.11.19

- 新增**第二种取帧方案**：MediaProjection 常驻流。首页「运行偏好 → 取帧方案」下拉框可在**无障碍截图**（默认，行为与之前一致）与**投屏常驻流**之间切换；切换只换“从哪拿一帧”，识别、判定、点击流程完全共用。
- 常驻流实现：`ProjectionService`（前台服务，Android 14+ 先以 `FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION` 入前台再取会话）+ `ProjectionStream`（`VirtualDisplay` + `ImageReader` 持续出帧）。系统截图两次之间至少间隔约 334ms，常驻流没有这个门限。
- 常驻流只保留会话，**暂停识别时一个像素都不拷贝**；识别期间按 250ms 节流缓存最近一帧，避免动画画面下每秒几十次全屏拷贝（12.8MB/帧）。
- **静止画面必须能复用缓存帧**：画面不动时系统不再合成新帧，`ImageReader` 不出图，若只等新图就会把“商店开着但没动”误判成取帧失败。现在等新图 120ms 无果时交付缓存帧。
- **点击后必须丢弃点击前的缓存帧**：`ProjectionStream.request(notBefore, …)` 只接受拍摄时刻不早于动作完成时间的画面，否则会拿点击前的画面再判一次、重复点击已买到的卡。
- 手势时序、动作闸门、OCR 帧缓存等既有判据两方案共用，未改动；投屏方案的取帧间隔为 150ms 自节流（不继承系统的 334ms）。
- 方案记录在 `SharedPreferences`（`captureScheme`），扫描启动时写入 trace（`capture=` / `projection_ready=`），每帧日志新增 `frame_lag_ms`。
- 权限新增 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PROJECTION`、`POST_NOTIFICATIONS`；常驻通知使用单色矢量图标 `res/drawable/jcc_notify.xml`（应用图标直接用于通知会在状态栏显示成白块）。
- 验证：`python tools/build_apk.py` BUILD SUCCESSFUL，apksigner 校验通过。**未做真机实跑验证**——投屏授权弹窗、常驻通知、以及部分 ROM 的投屏提示行为需真机确认。
