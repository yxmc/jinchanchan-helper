## v0.11.50

- **修复「误买拉克丝」等一排买错卡**：卡名容错校正 `ChampionCatalog.normalize()` 会把 OCR 结果向目标名单做一次编辑距离为 1 的收敛，但它只假设「目标名单内部不互为错字」，没考虑**商店里会出现与目标只差一个字的另一张真卡**。目标名单含「金克丝」时，OCR 正确读出的 **4 费拉克丝** 被改写成「金克丝」并当成目标买掉；同理目标含「沃里克」时「约里克」「塔里克」会被改写，目标含单字「蔚」时任何单字卡名（慎/彗/烬）都会被改写。
- 修法：收敛前先判「OCR 读到的原名是否已经是当前赛季棋池里的合法卡名」。是就不收敛、原样返回——**真正的 OCR 错字有个干净的共性：错字本身不在棋池里**（「料加斯」「破比」「德菜文」「璐路」都不是合法卡名），而「拉克丝」「塔里克」都是。这样既止住误买，又不影响补回真错字。
- 真机日志铁证（平板 / S16）：`[艾尼维亚, 娑娜, 雷克塞, 金克丝, 基兰] costs=[1, 1, 2, 4, 5]` —— 第 4 格名字是「金克丝」却读到 **4 费**，而 S16 金克丝是 3 费、**拉克丝正好 4 费**；同帧其余四格费用与目录逐一相符，只有它被改了名。随后 `dispatch slots=[3]` 把它买了两次。
- 连带保护：自举采集器 `TemplateCollector` 存字模用的是改写后的名字，被改名的那一帧可能把拉克丝的字形存成「金克丝」字模。本次已核对 `templates-pad` 里全部可疑条目（塔里克/蔚/金克丝/慎/沃利贝尔/布里茨），字形与卡名逐一相符，未发现错标；后续采集也不会再拿到被改写的名字。
- 新增 `tools/NormalizeCheck.java` 回归：断言「棋池内合法卡名一律不被改写」+「棋池外的 OCR 错字仍能收敛回目标」+「空值与无法收敛的名字原样返回」。

## v0.11.49

- **平板卡名字模从 5 个补到 69 个（覆盖率 4% → 58%）**，购牌识别率大幅提升。做法是新增**字模自举采集**：`TemplateCollector` 在跑识别时把「靠 OCR 认出、且名字在棋池里」的卡名掩码攒起来，攒够三次确认就落盘成字模，边玩边补，不需要手工截图标定。
- **三重校验**（缺一不可，否则会把误读固化成错字模，比没有更糟）：① 名字必须在当前赛季棋池里——实测 OCR 常把「璐璐」读成「璐路」「瑞璐」，这类错字不在池中，第一道就过滤掉；② 同一格必须连续 3 次读到同一个名字，且掩码两两自匹配 ≥ 0.95；③ 与已有字模交叉相似度必须 < 0.80，防止重复入库或形状冲突。
- 采集结果落在设备私有目录 `files/templates-learned/<卡名>.bin`，运行时**不写 assets**（assets 只读，且让运行时改字模会带来不可控漂移）。新增 `tools/import_learned_templates.py` 负责把拉回的采集结果合并进 `app/src/main/assets/<模板目录>/`：自动校验棋池、尺寸（274×55）、墨迹（≥60）、交叉查重（<0.80），并按序号追加 `nameN.bin` + 重写 `manifest.txt`，保证清单与文件严格一一对应。

- `analyze()` 里只把「模板未命中、靠 OCR 读出」的格子喂给采集器，避免用已有字模自我强化。
- 验证：`python tools/build_apk.py` BUILD SUCCESSFUL、apksigner v2 通过；合并后 `manifest.txt` 69 行与 `name0..name68.bin` 69 个文件严格对应；交叉相似度最大 0.65（奥恩 vs 赛恩），无重复。

## v0.11.46（已在 OPPO Pad 4 Pro 真机验证通过）

- **修复平板「阵容面板开着却被判成棋盘」**：`LineupVision` 里 `board` 的判据是「读到『购买经验』或图标命中」，而阵容面板是**浮在棋盘上方的半透明浮层**，底下的「购买经验」按钮与右上角菜单图标依然可见、依然能读到，于是 `board` 与 `menu` 同时为真。状态机 `PREPARE` 先判 `board`，就会反复去点「打开菜单」或「关闭面板」。现改为 `board = !(menu || replacement) && ...`。真机日志证据：修复前满是 `menu=false ... board=true` 后紧跟「确认应用并关闭面板」；修复后首次出现 `menu=true board=false` 并正常进入「阵容列表」。

- **平板跳过「点金币收商店」**：新增 `LineupLayout.Spec#canCloseShop`（手机 true / 平板 **false**）。平板上该交互**不存在**——实测助手连点 12 次、手动点同一位置都没反应，商店始终开着；旧逻辑在 `WAIT_CLOSED` 干等到超时，表现为「从 app 点导入打不开阵容收藏」。商店在屏幕底部、菜单图标在最顶部，两者不重叠，直接点图标即可，所以平板上不再等商店收起。收尾阶段 `WAIT_CLOSED_FINAL` 同样按机型分支。
- **`WAIT_CLOSED` 改为持续重发点击**（手机路径）：商店弹出有动画，落在动画帧上的点击会被游戏吞掉；金币面板本身没有交互，重发无副作用。

## v0.11.19

- 新增**第二种取帧方案**：MediaProjection 常驻流。首页「运行偏好 → 取帧方案」下拉框可在**无障碍截图**（默认，行为与之前一致）与**投屏常驻流**之间切换；切换只换“从哪拿一帧”，识别、判定、点击流程完全共用。
- 常驻流实现：`ProjectionService`（前台服务，Android 14+ 先以 `FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION` 入前台再取会话）+ `ProjectionStream`（`VirtualDisplay` + `ImageReader` 持续出帧）。系统截图两次之间至少间隔约 334ms，常驻流没有这个门限。

- 手势时序、动作闸门、OCR 帧缓存等既有判据两方案共用，未改动；投屏方案的取帧间隔为 150ms 自节流（不继承系统的 334ms）。
